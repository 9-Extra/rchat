# 用于AIRP的后端

一个究极简化版的SillyTavern，运行后启动一个后端并打开网站，和AI对话

为AI提供持久化代码环境，一个工具解决变量更新，复杂计算和状态记录的问题 

本项目不兼容SillyTavern格式的预设和角色卡，而是使用简化的版本

通过刻意的上下文组装设计。稳定输出选项，保证缓存前缀命中。

# 用法

运行环境要求 Python 3.14+

1. 配置 API key：复制 `config.yaml.example` 为 `config.yaml`，将 `api_key` 替换为你的真实 key。
2. 启动服务器：
   ```bash
   uv run -m main
   ```
   默认在端口 25530 上启动双栈访问的服务器，并自动打开浏览器。
 
# 多用户（放到服务器上跑）

默认 `auth.enabled: false`，任何能访问端口的人都能读写全部会话。
放公开服务器上时打开鉴权（注意密码明文直接传输，得靠https）：

```yaml
auth:
  enabled: true
  users:            # 账号手写在这里，改完保存即生效，不用重启
    alice: "强密码"
    bob: "另一个强密码"
  session_ttl_days: 30
  cookie_secure: true    # 走 https 反代时开
```

# 预设和角色卡
这两个概念来自SillyTavern，但本项目将它们大幅度简化

预设：功能上是在不同的世界观定义间通用的AI主持指南，定义的通用的文风，禁词表，防止全知等。逻辑上预设控制了如何基于对话历史和角色卡构造最开头的输入模型的上下文，包含系统提示词，也包含正文之后那次选项请求的选项指令。

角色卡：功能上它的作用已经远超“定义单个角色”，或者把它叫“规则书”更合适，定义了具体的世界背景，很多人物以及故事背景，开局等等。开局是卡里写好的候选第一句，玩家可以在对话区挑一段、改完再发，也可以在创建后自己写。卡在逻辑上就是几个大字符串，预设决定将它们插到上下文的什么地方。没有关键词匹配这类复杂规则，在现在模型上下文足够长且缓存命中价格远低于输入价格的情况下，破坏上下文前缀的损失>>>缩短输入带来的收益。

提供一个极简的默认预设（GM-safe）和一张默认的角色卡（很水），和一个改自《久远之旅》的中型角色卡。具体格式见AGENTS.md

# 对话页面
支持回滚和分支，AI输出修改，重Roll。
流式输出，思考块和工具调用默认折叠。
提供上下文预览功能（类似dsh的轨迹），完整展示将发送给AI的完整提示词上下文，包含输入框中的本次输入。
支持切换session和预设，支持指定角色卡和预设创建session。session内可以切换预设，但不能切换角色卡。
角色卡定义的开局以不同的块显示在对话开头，支持选择和修改，也可以自己写
支持上下文压缩
流式生成在服务端独立进行：切走不会打断当前会话，多个会话可以同时生成；侧栏显示「生成中」/「出错」，
切回来会从服务端事件缓冲重放接上，后台失败会在会话顶部显示一条可关闭的错误条。

# 历史保存
对话历史以jsonl格式保存在`./sessions/<用户名>/<name>`文件夹下（未启用鉴权时是 `./sessions/<name>`），其它需要保存的状态以json格式保存在同目录下另一个文件中。写入都是「先写临时文件再改名」，被 kill 或断电不会留下半截文件。
用户输入在开局时就落盘：生成中途进程被杀，那一轮不会凭空消失——界面上按钮会变成「继续」，点一下接着生成。第一句（也就是开局）同样先写进 state 的 `opening_input` 再发请求；它不在 history 里（只由预设的 `{{user_input}}` 渲染），所以重开这一轮走「开始」/「重新输出」都能带着它。

# 工具设计

预设 frontmatter 的 `tools` 列表决定本预设启用哪些工具（白名单，未定义时是 world_run + read_file），`tools: []` 表示正文之外不给任何工具。
world_run: 在持久的 Python 环境中执行一段代码，用于一切涉及数值与规则的判定与状态更新。这允许我们在卡中设计复杂的数值计算和真正的随机掷骰。
read_file: 读文件，这允许我们把卡组织成一组外部文档（参见[久远之旅](./games/久远之旅/久远之旅.md)），卡里只用放目录+索引，AI自主选读需要的部分，而不是全量塞入上下文。
write_file / edit_file: 写文件，以及把文件里的一段文字精确替换掉。AI 因此能把笔记、存档、生成的内容落到磁盘上（相对路径以角色卡所在目录为基准，也接受绝对路径）。
bash: 在角色卡所在目录里执行一段 shell 命令（Git Bash），适合批量处理文件、跑脚本、查环境这类事情。命令有超时上限（默认 60 秒，最多 600 秒）。
web_search / web_fetch: 联网搜索与网页抓取，打的是 DeepSeek 的 Search / Fetch 接口（前者返回标题/链接/摘要，后者把单个网页抓成 Markdown），用于实时信息。这两个工具与模型端点**独立配置**：在 `config.yaml` 的 `web_tools` 段填 `api_base` 与 `api_key`（实际就是 DeepSeek API Key，把端点那个 key 复制过来即可），没配这一段时调用它们只会得到一个配置错误提示，不影响其它工具。
选项: 正文流式输出结束后，服务端会再发一次独立请求，指令来自预设的 `<preset_options>` 块（未定义时回退到 `core.OPTIONS_INSTRUCTION`），让模型一行一条地输出选项（每行以「- 」开头，没有合适选项时输出单独一行「无」），解析后写进该轮 entry 的 options 字段；这次调用不进上下文。写了自己的 `<preset_options>` 后，选项的条数与引导方向完全由预设决定；输出格式仍是编写该块时的固定规范（见 AGENTS.md），解析器不随预设变化。前端可按会话关掉它（state 的 `options_enabled` / `POST /api/sessions/{name}/options`），也可以只把选项重掷一次（`POST /api/sessions/{name}/regenerate_options`）。选项没解析出来（或预设块为空/宏出错）不会影响正文：错误记在 entry 的 `options_error`，模型这次的原始输出记在 `options_raw`（重试的各次分别标注），前端在「选项生成失败」那一行下面折叠显示，服务器日志里也有全文。
